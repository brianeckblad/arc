# ARC Settings — User-Editable Files

Everything in this folder customizes ARC **without touching code**.
Edit a file, save, restart ARC. That's it.

| File / dir | What it controls | How to edit |
|------------|------------------|-------------|
| `features/` | Which commands are turned **on / dev / off** — one JSON file per domain | Set a flag to `true`, `"dev"`, or `false` |
| `commands.json` | Hide/show **individual** commands, independent of feature flags | Add `"<command>": false` to hide one |
| `banner.txt` | The startup logo / banner | Plain text + Rich colour tags like `[bold cyan]…[/bold cyan]` |
| `goodbye.txt` | Random exit messages (one per line) | Add/remove lines |
| `theme.json` | Colours used in `?` help and prompts | Rich style strings: `"cyan"`, `"bold yellow"`, `"dim"` |
| `cli-structure.yaml` | Verb descriptions, section headers, help footer, configure banner | YAML key/values |
| `command-structure.json` | The **order** of fields for curated `set <object>` commands | Move field names in the array |
| `panos-sources.json` | Which PAN-OS docs pages the command catalog is built from | Add a page entry per new PAN-OS version |

> **Command help text** (the one-liner + usage shown by `?` and the full
> `help <command>` page) is **not** here — it lives in that command's
> `docs/commands/<command>.md` front-matter, when such a file exists.
> Commands without a doc file get help synthesized automatically.

Validate after editing: `python dev/smoke_test.py --only 7,8,9,10`.

## features/ — turn commands on and off

The most important directory: the **feature-flag glossary**, split into small
per-domain files so each is readable on its own:

- `scm-<spec>.json` — one file per SCM API spec (e.g. `scm-ngfw-objects.json`).
  SCM resources get **per-operation flags**: `show_<resource>` (read),
  `create_<resource>` / `update_<resource>` / `delete_<resource>` (write) —
  so you can allow reading addresses while keeping deletion off.
- `panos-ops.json` — PAN-OS operational command **families**
  (`panos_debug_ike`, `panos_clear_routing`, …) plus curated live-device
  commands. All PAN-OS families default off.
- `panos-config.json` — the PAN-OS device-local config tree: **break-glass
  recovery only**. `panos_config_recovery` stays `true`; enable other
  `panos_config_<family>` flags only when SCM is unreachable.
- `curated.json` — fallback for flags with no derivable domain (normally
  absent/empty).

Each flag has one of three states:

```json
{
  "show_address": true,       // ON  — visible and runnable for everyone
  "nat_rules":    "dev",      // DEV — hidden until development mode
  "delete_objects": false     // OFF — hidden and blocked for everyone
}
```

A flag **missing** from every file defaults to **off** (fail closed). Keys
starting with `_` are comments — ignored. The file structure is regenerated by
`python dev/generate_feature_flags.py` (and by docsupdate); **your values are
always preserved** — only edit values, not the layout.

### Development mode — test work-in-progress commands

`"dev"` commands stay invisible to normal users. Reveal them with the hidden
`dev` command (`dev` / `dev on` / `dev off` — prompt shows `arc:global:dev >`),
or start ARC with `ARC_DEV_MODE=1`. Lifecycle: ship a command as `"dev"`, test
it in dev mode, flip it to `true` here when ready.

**Inside ARC** (one session only, not saved):

```
feature show                 list every flag grouped ON / DEV / OFF
feature find <text>          search flags AND the commands they gate
feature enable show_zone     set one ON for this session
feature disable show_zone    set one OFF for this session
feature dev show_zone        mark one DEV for this session
```

One-shot/CI override: `ARC_FEATURE_<NAME>=on|dev|off`.

## commands.json — hide individual commands

Independent of feature flags: features gate functional areas; this file hides
one specific command (e.g. deprecate `show devices` without touching code).
Set `"show devices": false`. Keys starting with `_` are comments.

## command-structure.json — argument order for curated `set` commands

One entry per curated command: the object type is the key, the value is the
field names **in the order you type them**:

```json
{ "address": ["name", "type", "value", "description", "tag"] }
```

- Reorder by moving names in the array — that is all you edit here.
- Which fields are choices, the choices themselves, required-ness, Tab/`?`
  hints all come from the API-derived field library in code, never this file.
- **No quotes needed** around values with spaces — ARC works out where each
  field ends (`set address my web host fqdn example.com`).
- An entry here always **wins** over the auto-generated field catalog; a
  command with no entry falls back to its usage line / the generated catalog.

Validate: `python dev/smoke_test.py --only 4`.

## panos-sources.json — PAN-OS docs registry

The pages `dev/panosupdate.py` pulls to build the built-in PAN-OS command
tree. To pick up a new PAN-OS version, add entries to `"pages"`:

```json
{"key": "new-show-12.2", "url": "https://docs.paloaltonetworks.com/.../new-show-commands-12-2",
 "kind": "added", "version": "12.2"}
```

`kind` is one of `ops-hierarchy`, `config-hierarchy`, `added`, `deleted`.
Then run `python dev/panosupdate.py && python dev/generate_panos_catalog.py`
(docsupdate runs both automatically). Deleted commands become version
tombstones, never silent removals.

## Where secrets live (NOT here)

Credentials (API tokens, SSH passwords) are **never** stored in this folder.
They live in the OS keychain + `config/<your-username>/config.json`
(non-sensitive values only). Run `arc auth configure` to set them. Personal
terminal preferences and aliases live in `config/<your-username>/preferences.json`
via the `terminal` and `alias` commands.
