# `app/commands/` — The Command Registry

Every runnable command is a `CommandDef` in one of these modules. The registry
merges them; the shell dispatches into them. No dispatcher edits are ever
needed to add a command.

## What lives here

| File | One line |
|---|---|
| `base.py` | `CommandDef`, `ExecutionContext`, `require_scm`/`require_device` guards, `show_handler()`/`delete_handler()` factories |
| `registry.py` | Thin merger of all modules + `match_command()` (longest-prefix match) |
| `setup.py` / `objects.py` / `security.py` / `network.py` / `identity.py` / `operations.py` | Curated domain modules — one per SCM URI domain |
| `operations.py` | Also owns the SLS-backed `show log traffic|threat|system` + `show log detail <n>` |
| `config_view.py` | `show config running/versions/format set` + `load config version <id>` rollback |
| `packet_tracer.py` | Cisco-ASA-style policy simulation against the active folder's rule base |
| `resource_catalog.py` | **AUTO-GENERATED** endpoint catalog from the pulled OpenAPI specs |
| `generated.py` | Factory: catalog entry → feature-gated command (GET→show, POST→set, PUT/PATCH→update, DELETE→delete) + field validation (`pattern`/`maxLength`) |
| `panos_catalog.py` | **AUTO-GENERATED** PAN-OS CLI command catalog from `docs/panos-cli/` mirrors |
| `panos_generated.py` | Factory: PAN-OS catalog entry → CommandDef (SCM ops-job / `--remote` guidance / break-glass config) |

## How the pieces relate

Merge order in `registry.py` (later shadows earlier):
**OpenAPI-generated < PAN-OS-generated < curated/explicit.** A hand-written
command with the same key always wins. Every command carries an explicit
`scope=` (`folder` | `device` | `remote` | `global`) and usually a `feature_flag`
resolved against `settings/features/`.

## How to change things here

- New curated command: follow the AGENTS.md "Add a Command" recipe — pick the
  domain module, add a `CommandDef` with explicit `scope=`, flag it `"dev"` in
  `settings/features/`. Stub: `python app/scripts/scaffold.py "show bgp routes" network`.
  Validate: `python app/scripts/smoke_test.py --only 1,2,3`.
- New SCM endpoint wrapper: one-line getter on `SCMClient`
  (`app/api/client.py`) — look the endpoint up in `app/scripts/API_INDEX.md` first.
- Catalog drift (smoke §3 failure): `python app/scripts/generate_resource_catalog.py`.
- PAN-OS behavior tweaks (scm mappings, recovery stems, overrides): edit
  `app/scripts/panos-curation.json`, then `python app/scripts/generate_panos_catalog.py`.
  Full suite afterwards.
- Generated `set` field syntax: regenerate with
  `python app/scripts/generate_field_library.py` (writes `app/settings/field_catalog.py`).

## Do not

- Never hand-edit `resource_catalog.py` or `panos_catalog.py` — regenerated by
  `app/scripts/generate_resource_catalog.py` / `app/scripts/generate_panos_catalog.py`.
- No lambdas as handlers (smoke enforces named module-level functions).
- Never swallow API errors into `[]` — raise; `_execute_api` renders them.
- Never create doc stubs for generated commands — help is synthesized from the
  CommandDef at runtime.
- Never mark network *config* commands as `scope="device"` — that data is SCM's.
